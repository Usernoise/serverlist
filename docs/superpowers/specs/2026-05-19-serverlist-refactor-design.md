# ServerList — рефакторинг и доработка выпадающего меню

**Дата:** 2026-05-19
**Статус:** утверждён пользователем

## Контекст

ServerList — macOS-приложение в статус-баре для управления локальными dev-серверами
(PHP `php -S` и Python `http.server`). Кодовая база: Swift 5.10, SwiftPM (`swift build`),
6 файлов (~950 строк). Сборка бинарника копируется в `ServerList.app`. `LSUIElement`
в `Info.plist` уже выставлен в `true`.

Задачи пользователя:
1. Полный рефакторинг и исправление багов.
2. Сделать выпадающее меню в статус-баре полноценным и удобным.

## Решения (зафиксированы с пользователем)

- **Роль popover:** «быстрый доступ» — старт/стоп/перезапуск/браузер. Добавление,
  редактирование, удаление серверов и список системных процессов остаются в главном окне.
- **Кнопка «Обновить»:** означает перезапуск конкретного сервера (per-server, в строке).
- **Поведение приложения:** только статус-бар (агент). Нет иконки в Dock, окно не
  открывается при запуске; открывается по кнопке «Открыть окно».
- **Баги к исправлению:** №1, №2, №3. Баг №4 (жёстко зашитые пути PHP/Python) НЕ трогаем.
- **Ошибки запуска:** показывать пользователю (в окне и в popover).

## Подход

Точечный рефакторинг существующей структуры из 6 файлов. Все мутации состояния
централизуются в `ServerManager`; первопричины багов устраняются за счёт удержания
объектов `Process` и `terminationHandler`. Структура файлов не меняется.

## Архитектура

| Файл | Изменения |
|---|---|
| `Models.swift` | Без изменений. |
| `main.swift` | Без изменений. |
| `ServerManager.swift` | Центр всех мутаций. Новое: `deleteServer(id:)`, `restartServer(id:)`, словарь `[UUID: Process]` для удержания процессов, `terminationHandler`, бэкап-`Timer`, `@Published lastError`. Чинятся баги №1–№3. |
| `AppDelegate.swift` | Не открывает окно при запуске. Управляет activation policy при открытии/закрытии окна. «Выход» = полный quit. |
| `ContentView.swift` | Мутации только через `ServerManager`. Добавляется sheet редактирования сервера (подключение мёртвого `updateServer`). Алерт ошибок. |
| `StatusBarPopoverView.swift` | Переделка под «быстрый доступ»: компактные строки, кнопки старт/стоп, перезапуск, браузер; инлайн-ошибки; footer «Открыть окно» / «Выход». |

## Детали компонентов

### ServerManager

- `deleteServer(id:)` — если процесс жив, послать `SIGTERM`; удалить из массива;
  убрать из словаря процессов; `saveServers()`. Заменяет все прямые
  `servers.removeAll { ... }` в вью.
- `restartServer(id:)` — остановить (если работает), дождаться освобождения порта
  (поллинг `isPortAvailable` с таймаутом, напр. до ~2 с), запустить заново; вернуть
  `String?` с ошибкой. Заменяет хрупкий `DispatchQueue.main.asyncAfter(0.3)` в popover.
- Словарь `private var processes: [UUID: Process]`. В `startServer` объект `Process`
  сохраняется в словарь; задаётся `task.terminationHandler`, который на главной
  очереди ставит `isRunning = false`, `pid = nil`, удаляет из словаря и сохраняет —
  при условии, что pid совпадает (чтобы не затирать перезапущенный сервер).
- Бэкап-`Timer` (repeating, ~5 с): для каждого работающего сервера `kill(pid, 0)`;
  если процесс мёртв — сбросить статус и сохранить. Покрывает процессы из прошлой
  сессии и убитые извне. Таймер запускается в `init`, инвалидируется при необходимости.
- `checkServerHealth(id:)` — починить захват устаревшего `index` (искать индекс
  внутри `DispatchQueue.main.async` по `id`, а не снаружи).
- Вывод процесса: `task.standardOutput` и `task.standardError` → `FileHandle.nullDevice`
  (баг №2 — исключает переполнение pipe-буфера и зависание).
- `@Published var lastError: ServerError?`, где
  `struct ServerError: Identifiable { let id: UUID; let serverID: UUID; let message: String }`.
  Устанавливается при неудаче `startServer`/`restartServer`; сбрасывается при успешном
  старте этого сервера.

### AppDelegate

- Убрать `window.makeKeyAndOrderFront(nil)` из `applicationDidFinishLaunching`
  (окно создаётся, но не показывается).
- `openApp()` — `NSApp.setActivationPolicy(.regular)`, `makeKeyAndOrderFront`,
  `NSApp.activate(ignoringOtherApps: true)`.
- Назначить `window.delegate`; в `windowWillClose` — `NSApp.setActivationPolicy(.accessory)`.
- `quitApp()` — остановить все серверы, `NSApp.terminate(nil)`. Привязать к кнопке
  «Выход» в popover.

### Popover (StatusBarPopoverView)

Компактный список, одна строка на сервер. Раскладка:

```
┌─ ServerList ──────────────────┐
│  ● Мой сайт      :8080         │
│              [↻] [🌐] [■]      │
│ ───────────────────────────── │
│  ○ API           :3000         │
│                       [▶]      │
│ ───────────────────────────── │
│  ⚠ Docs — порт 4000 занят      │
│                       [▶]      │
│ ───────────────────────────── │
│ [ Открыть окно ]   [ Выход ]   │
└────────────────────────────────┘
```

- Точка статуса (зелёная — работает, серая — остановлен), имя, `:порт`.
- Кнопки строки:
  - **▶ / ■** — toggle старт/стоп (через `ServerManager`).
  - **↻** — перезапуск (`restartServer`), показывается только когда сервер работает.
  - **🌐** — открыть `http://localhost:<порт>` в браузере, только когда работает.
- При ошибке старта/перезапуска под именем сервера — инлайн-строка с текстом из
  `lastError` (значок ⚠ + сообщение). Сбрасывается при следующей успешной попытке.
- Footer: «Открыть окно» (открывает главное окно через `onOpenApp`) и «Выход»
  (полный quit приложения). Закрытие popover — клик вне (существующий event monitor /
  `.transient`).
- Пустое состояние: «Нет серверов» + подсказка открыть окно для добавления.

### ContentView (главное окно)

- `deleteServer` использует `serverManager.deleteServer(id:)` (не прямой
  `servers.removeAll`).
- Старт/стоп через `ServerManager`; результат-ошибка показывается через `.alert`,
  привязанный к `serverManager.lastError`.
- Добавить кнопку/иконку «редактировать» в строке сервера → sheet с формой
  (имя, тип, папка, порт), при сохранении — `serverManager.updateServer(...)`.
  Это подключает существующий мёртвый код `updateServer`.
- Кнопку запуска браузера и `URL(string:)!` обернуть безопасно (без force-unwrap,
  на случай некорректного порта).

## Обработка ошибок

- Единый источник: `ServerManager.lastError`.
- Окно: `.alert(item: $serverManager.lastError)` с сообщением и кнопкой OK.
- Popover: инлайн-текст в строке соответствующего сервера.
- Force-unwrap `URL(string:)!` заменить на безопасное разворачивание (guard / early return).

## Тестирование

Проект без модульных тестов и без UI-харнеса; GUI-приложение не тестируется
автоматически в этой среде.

Критерии готовности:
1. `swift build` проходит без ошибок и без новых предупреждений.
2. Ручной чек-лист (выполняет пользователь):
   - Приложение стартует без окна и без иконки в Dock; иконка в статус-баре есть.
   - «Открыть окно» открывает и фокусирует окно; закрытие окна возвращает агент-режим.
   - Старт сервера → статус зелёный, доступен в браузере.
   - Стоп → статус серый, процесс убит (`lsof -i :<порт>` пусто).
   - Перезапуск (↻) → сервер снова доступен, без дубля процесса.
   - Удаление работающего сервера → процесс убит, сервер не возвращается после
     перезапуска приложения.
   - Старт на занятом порту → видимая ошибка в окне и инлайн в popover.
   - Запуск «болтливого» сервера (много запросов) → не зависает.
   - Внешнее убийство процесса (`kill`) → статус в приложении становится серым в
     течение ~5 с.
   - «Выход» из popover завершает приложение и останавливает все серверы.

## Вне скоупа

- Баг №4: автоопределение путей PHP/Python — НЕ делаем (по решению пользователя).
- Добавление/редактирование серверов из popover — остаётся в главном окне.
- Просмотр логов серверов, тёмная/светлая темизация, локализация — не входят.
